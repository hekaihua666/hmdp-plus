# 分类筛选与演示数据说明

## 本次解决的问题

- 原下拉面板相对五等分的单个按钮定位，导致价格区间折行。现在所有筛选共用整行宽度的面板，使用双列选项、数量和比例条，375px与桌面均可使用。
- 普通分类浏览走 Redis GEO，原本没有 ES 聚合。现在保留 GEO 列表，额外用同分类、同演示坐标和5公里范围查询 ES 统计；选择关键词、价格、评分、距离或排序后使用原组合搜索。
- 数量为0的桶也显示；请求失败展示“统计暂不可用”及重试入口，不把失败当作0家。快速切换分类用请求代号忽略旧响应，翻页成功才前进，到尾停止。
- 聚合是**当前结果分布**：包含已选的其他条件和该维度本身，因此选择一个价格区间后，其他价格区间通常为0。页面已说明这个含义；它不是排除当前维度条件的多面筛选统计。
- 距离面板已补齐累计数量与比例条：1、3、5、10公里内对应`distanceAgg`，有参考坐标才返回。使用[ES filters聚合](https://www.elastic.co/guide/en/elasticsearch/reference/7.17/search-aggregations-bucket-filters-aggregation.html)和与真实筛选一致的`geo_distance`条件，避免范围边界统计不一致。各桶包含当前全部筛选条件，范围存在重叠，数量不能相加；纯GEO分类浏览的统计仍限定当前附近5公里结果。
- 页面继续使用杭州固定参考坐标，尚未读取设备定位。没有统计或请求失败时显示“暂不可用”和重试，不把缺少桶或请求失败当成0家。
- 详情移除固定的口味评分、榜单、119条评价和重复评论，改为真实店铺字段、优惠信息及关联探店笔记。笔记正文和点赞名单支持游客阅读，发布、点赞、关注与个人动态仍需消费者登录。

1. 首页点击任意分类，浏览附近店铺；搜索中文、拼音或首字母并使用补全。

5. 游客阅读笔记；用现有消费者登录流程后点赞、取消点赞、关注或发布。演示券不能用于真实消费、支付或核销。

## 显式导入与重复执行

源码：`scripts/seed_demo_data.py`。脚本读取本机`application.yaml`及相应环境变量，凭据不会写入清单或输出。

```powershell
# 先安装到合适的本机Python环境；本轮使用既有QA虚拟环境执行。
python -m pip install pymysql pyyaml redis
python scripts/seed_demo_data.py          # 只显示计划，不写数据库
python scripts/seed_demo_data.py --apply  # 显式导入

# MySQL导入后补齐ES；不删除索引，复用ShopDoc.from生成拼音、首字母和补全字段。
mvn '-Dtest=DemoIndexSyncTest' '-Dhmdp.demo.sync=true' test
mvn package
```

- 一次MySQL事务写入新数据；Redis只补充本批GEO与新库存，重复执行不重置已消耗库存。
- `target/demo-data/manifest.json`保存本批所有新增ID，不含密码、token或原用户数据。重复执行先验证所有记录仍存在且保留演示标识，校验通过就跳过插入。
- 清单也已备份到本轮本机备份目录。`mvn clean`会移除target；若清单丢失但数据库演示标识仍存在，脚本会停止，避免再次导入。需要先从备份恢复清单，再操作。
- 普通`mvn test/package`默认跳过真实索引同步和其他显式维护命令，不能在构建时自动往真实数据库加数据。
- 本轮操作前已备份源码和相关表。需要撤回时应先用清单确认新增ID与后续笔记、订单、关注等关联；只处理本批数据，不能清空业务表。只恢复源码不会自动删除已新增的数据库记录。
- Redis与ES同步不是与MySQL同一个事务。若外部同步失败，保留清单，再分别补齐；当前仍沿用原项目的异步同步边界，没有新增可靠事件队列或持久补偿。

## 摄影素材替换与重复执行

脚本`scripts/refresh_demo_photos.py`只处理原导入清单中的演示数据，默认不改数据库。素材来源、描述、ID与本地路径集中保存在`scripts/demo_photo_catalog.json`。

```powershell
python scripts/refresh_demo_photos.py             # 显示计划
python scripts/refresh_demo_photos.py --download  # 下载本地960px摄影素材
python scripts/refresh_demo_photos.py --apply --backup-dir '/path/to/local-file
```

- 餐饮封面优先环境照；游泳、攀岩、球类、瑜伽、美睫和亲子手作按店名选择对应场景。不同店铺选择不同的三图组合，详情使用等比裁切，避免拉伸变形。
- 所有下载成功并确认本地文件存在后，才允许执行数据库替换；原14家店和原4篇笔记不在更新清单内。清单中的店铺如果使用了自定义外部图片也会跳过，不覆盖用户上传的图片。
- 旧图片字段与关联笔记正文保存到备份目录的`images-before.json`，重复执行不覆盖最初快照。只更新图片与正文末尾的素材说明，店铺其余信息、笔记主体、账号与优惠库存保持。
- MySQL事务提交后，只更新这200家店的ES `images`字段，再删除对应`cache:shop:<id>`缓存；不重建索引，不修改GEO、拼音补全或秒杀库存。外部同步失败可重跑补齐；这不是跨MySQL、Redis、ES的原子事务。
- `imgs/demo/photos/download-manifest.json`记录本地图片大小与SHA-256。下载源下架或失败会明确停止，不用破图或通用图片冒充成功。
- 本轮只更新静态页面、素材与演示图片数据，无需打包或重启后端。截图与只读验收保存在`/path/to/local-file`。
