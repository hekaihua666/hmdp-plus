# 商户后台：桌面网页与后端最小闭环

## 范围

独立商户账号，一账号一店；电脑网页支持登录、查询和编辑自己的店铺、退出。消费者查询保持原URL，不做公开注册、自主开店、店铺认领、订单管理或优惠券管理页面。

## 数据库与初始化

新数据库依次导入 `database/schema.sql`、`database/merchant-schema.sql`、`database/demo-data.sql`。已有数据库可使用以下显式工具：先备份店铺，再检查元数据创建商户表、补充owner_id和唯一索引。原课程坐标为无符号，本版编辑接受全球合法经纬度，因此迁移为有符号DOUBLE。

```powershell
$env:MERCHANT_A_PASSWORD = '<商户甲的8至64位初始密码>'
$env:MERCHANT_B_PASSWORD = '<商户乙的8至64位初始密码>'
# 默认绑定已有店铺1、2；可通过以下变量改为其他已有店铺。
$env:MERCHANT_A_SHOP_ID = '1'
$env:MERCHANT_B_SHOP_ID = '2'
mvn '-Dtest=MerchantSetupTest' '-Dhmdp.merchant.init=true' test
Remove-Item Env:MERCHANT_A_PASSWORD, Env:MERCHANT_B_PASSWORD
```

初始化建立 `merchant_a`、`merchant_b` 演示账号，密码以BCrypt哈希保存；不重置已存在账号密码，不覆盖其他账号的店铺归属。第一次执行前快照在 `target/merchant-shops-before.json`。DDL不具有整体回滚保证；普通mvn test不会迁移数据库或创建商户。

owner_id可空，未绑定课程商户继续供消费者查询；唯一索引限制一账号一店。

## 页面和接口

后端8081、Nginx8080时，打开 `http://localhost:8080/merchant/login.html`。页面在 `src/main/resources/nginx-1.18.0/html/hmdp/merchant/`，使用现有Vue/Element UI，不加载消费者common.js。

| 接口 | 功能 |
| --- | --- |
| POST /admin/merchant/login | 登录，返回随机token |
| POST /admin/merchant/logout | 撤销当前token |
| GET /admin/merchant/me | 脱敏账号信息 |
| GET /admin/shop | 查询自己的店铺 |
| PUT /admin/shop | 编辑自己的店铺 |

使用authorization请求头；商户Redis前缀为login:merchant:，固定两小时有效期。页面使用merchant_token，与消费者token隔离。每次请求确认数据库账号启用状态，停用后旧token也不能访问；退出只撤销当前会话。

## 编辑与同步

ShopUpdateDTO只接收名称、分类、图片地址、商圈、地址、经纬度、人均价格和营业时间。未知字段被拒绝，不能提交店铺ID、归属、销量、评论数量或评分。该接口接收完整表单，不是任意字段PATCH。

ShopServiceImpl从MerchantHolder取得商户ID，锁定自己的店铺，更新SQL再次限定owner_id。成功后在同一事务发布ShopChangedEvent，复用提交后Redis缓存/GEO更新和异步ES同步。后台直接读取数据库填充编辑表单，保存成功不等于搜索已立即刷新。

图片第一版支持地址编辑和预览，没有上传功能。服务器不抓取外部图片；浏览器请求填写的地址。地址支持http(s)或以单个斜杠开头的本地路径。

## 旧入口与验证

原POST /shop、PUT /shop、POST /voucher、POST /voucher/seckill已移除HTTP映射。原店铺新增/更新服务方法仅保留给受控维护和事务回归测试。当前已有商户发券页面merchant/voucher.html及POST /admin/voucher，服务端根据登录商户定位自己的店铺，不能恢复公开写入口。最新运行问题核查见[问题核查与停机修复](问题核查与停机修复.md)。

普通测试覆盖真实MVC拦截器隔离、密码匹配和会话、编辑白名单、SQL归属条件、提交/回滚副作用。外部存储使用替身，不等于真实服务或浏览器验收。

当前仍没有持久同步重试、并发版本控制、公开注册审核、密码找回、登录限流或多店员工权限。原消费者笔记上传等其他业务不属于本轮改造范围。
