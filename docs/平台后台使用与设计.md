# 平台后台使用与设计

## 入口与当前能力

- 平台网页：<http://localhost:8080/platform/login.html>，登录后进入商户管理列表。
- 本机教学管理员：账号`admin`，初始密码`123456`。初始化只创建缺失账号，不会重置已存在账号的密码或停用状态；可通过`PLATFORM_ADMIN_PASSWORD`环境变量指定首次初始化密码。
- 支持管理员登录、退出、身份查询；店名/商圈/商户名称/账号搜索、启用状态筛选、分页、查看关联店铺、封禁与解封。
- 当前214家店铺均有独立商户账号：保留原2户，为原先未绑定的212家门店补齐账号和归属，继续遵守一账号一店。列表查真实账号，每页20条，共11页，并非仅展示店铺的假账号。
- 封禁控制商户后台登录和操作权限。顾客仍可浏览已发布店铺；已开始执行的请求不会因之后的封禁而被自动中断。

## 页面操作

1. 登录平台，列表首先展示门店照片、店名、分类、商圈与地址，再展示账号、商户ID、状态及操作；点击店名可打开顾客端门店详情。
   - 图片来自门店现有图片字段，取首图；图片失败显示门店占位图。已有学习素材不是本店实景，不能据此认定真实商家。
   - 表格内部滚动，表头及分页保持可见；1024和1440桌面宽度无需横向拖动。
2. 用搜索和状态下拉缩小范围，点击“封禁”并确认，账号变为“已封禁”。取消确认不会修改状态。
3. 商户下一次后台请求返回401，前端清除商户登录态并跳转登录页；有未保存修改也不会挡住失效后的跳转。
4. 点击“解封”，恢复账号登录资格；旧token仍失效，商户需要重新登录。
5. 平台“退出登录”只清理平台身份，不修改同一浏览器中的消费者或商户存储键。服务端登出失败时也完成本地退出，剩余服务端会话按固定TTL过期。

## 三类身份的边界

| 身份 | 账号表 | 接口范围 | Redis前缀 | 浏览器存储键 |
| --- | --- | --- | --- | --- |
| 消费者 | tb_user | C端个人操作 | login:token: | token |
| 商户 | tb_merchant | /admin/** | login:merchant: | merchant_token |
| 平台管理员 | tb_admin | /platform/** | login:admin: | platform_token |

- 管理员与商户都使用BCrypt密码哈希、随机token和固定两小时登录态；本次没有新增JWT或全套RBAC。
- `WebMvcConfig`把`/platform/**`从消费者拦截器中排除，再交给`AdminLoginInterceptor`；唯一匿名平台接口是`/platform/admin/login`。
- `AdminHolder`、`MerchantHolder`、`UserHolder`相互独立。平台拦截器在请求结束后清理ThreadLocal，服务层也要求管理员身份。
- 平台token不能替代商户或消费者个人操作的登录态，商户与消费者token也不能管理平台商户列表。
- 列表使用`PlatformMerchantDTO`白名单，查询时就不选择密码与会话版本；状态请求仅允许`status`，不能夹带密码、归属或版本字段。

## 为什么不能只改一行status

旧实现每次从Redis读取商户ID，再查询数据库的启用状态；封禁时，下次请求确实会被拒绝并删除该token。但封禁期间未请求过的其他旧token仍留在Redis，解封后可能重新有效。

这次给商户增加`session_version`，默认0：

```text
商户登录 → Redis保存 token => 商户ID:版本号
平台封禁 → 单条SQL同时 status=0、session_version+1
商户请求 → 状态禁用或版本不匹配 → 删除当前token并返回401
平台解封 → 只改status=1，版本保持
商户重新登录 → 获取新版本token，正常访问
```

- 同一条SQL完成状态与版本变更，没有“已封禁但版本还没更新”的中间状态。
- SQL仅对当前启用账号递增版本，重复封禁不重复递增。
- 封禁过程中刚生成的旧版本token也会在认证时失效，不需要扫描Redis会话。
- 升级前只保存商户ID的会话兼容为版本0，因此本轮不会把原商户全部强制退出；首次封禁后旧格式会话同样失效。
- 这些操作不修改店铺、Redis GEO、ES文档、优惠券或秒杀库存，也不改变店铺归属。

## 接口约定

网页经Nginx调用时加`/api`，例如`/api/platform/merchant`；下表是后端路径。

| 方法与路径 | 请求 | 用途 |
| --- | --- | --- |
| POST /platform/admin/login | username、password | 管理员登录，返回token |
| POST /platform/admin/logout | authorization头 | 注销当前平台会话 |
| GET /platform/admin/me | authorization头 | 当前管理员ID与账号 |
| GET /platform/merchant | keyword、status、current、pageSize | 分页商户列表 |
| PUT /platform/merchant/{id}/status | status：0或1 | 封禁/解封指定商户 |

- 商户分页响应在`data`内包含`records`、`total`、`current`、`size`等分页信息，每页最多100条。
- 搜索先查匹配店铺的owner_id，再合并账号名称/账号条件进行数据库分页，避免分页后筛店名导致总数错误。
- 关联店铺与分类分别批量查询，避免对每行账号单独查询；列表新增shopCover、shopTypeName、shopArea、shopAddress展示字段，不返回认证信息。
- 登录态无效返回401，非法状态、页码或夹带字段返回400；不存在商户返回`success=false`。

## 初始化与验证

```powershell
# 显式本机初始化：建tb_admin、补商户版本列、仅创建缺失的教学管理员。
mvn '-Dtest=PlatformSetupTest' '-Dhmdp.platform.init=true' test

# 默认测试不执行上述初始化，也不修改真实数据库。
mvn test

# Windows下先核对并停止正在使用同一jar的后端，再打包和启动，避免文件占用。
mvn package
```

- 建表SQL：`database/platform-schema.sql`；已有商户表一次性迁移参考`database/migrations/20261012-platform.sql`。
- `PlatformSetupTest`在迁移前检查列是否已存在，重复执行不重复加列、不重置管理员密码、不更改商户状态。
- 平台基础版50项默认测试通过，另5项显式维护/集成测试默认跳过；显式初始化通过。53项真实接口和Edge检查使用临时商户，验证身份隔离、封禁/解封、旧token失效及按钮与退出，结束后清理。
- 全量商户及页面改造再次通过50项默认测试（5项维护测试跳过）、构建，以及300项只读数据库/接口/Edge检查：214家门店资料核对、11页无重复和遗漏、店名/商圈搜索、十类新账号真实登录与本人归属、图片失败占位、1024/1440布局及分页按钮可见。原2商户的密码哈希、状态、资料与归属保持。
- 续接时优先阅读`AdminServiceImpl`、`AdminLoginInterceptor`、`WebMvcConfig`、`MerchantServiceImpl`和`platform/platform.js`。
- 本轮源码备份、迁移前表结构/数据指纹、构建与验收结果：`/path/to/local-file`。临时测试账号不属于交付数据。

## 补齐已有店铺的商户账号

这是一条显式本机初始化命令，不是公开入驻接口。使用已安装pymysql、PyYAML、redis和bcrypt的Python环境，在项目根目录执行：

```powershell
# 默认只检查数量、归属是否有效及账号名是否冲突，不写库。
python scripts/provision_shop_merchants.py

# 明确执行，完整本机快照和账号清单默认写入Git忽略的target/merchant-accounts。
python scripts/provision_shop_merchants.py --apply

# 可以用--output-dir指定项目外的本机目录，避免mvn clean删除随机密码清单。
```

- 本次新增账号格式为`shop_<门店ID>`，每户生成独立随机初始密码；数据库只保存BCrypt哈希，CSV清单含初始密码，仅保留本机，不能提交或公开。
- 脚本仅处理owner_id为空的店铺，不修改已绑定账号、不重置密码、不更改既有状态。同名冲突或异常归属直接停止，所有创建和绑定在同一个MySQL事务内完成。
- 重复执行检查结果为214户、0家未绑定，不新增账号；今后新增未绑定店铺须明确再次执行。网页不自动创建账号。
- 本次账号清单与写库前完整快照：`/path/to/local-file`；源码备份、验收记录和截图在其上一级目录。
- 仅改变owner_id等归属信息；门店名称、图片、价格、坐标及优惠库存不重写。归属字段不进入ES搜索文档，商户端按数据库身份读取本人门店。

## 最小范围

这版只提供一类平台管理员和账号状态管理，没有开放管理员注册、商户入驻绑定、审核流、封禁原因与操作审计。如果后续做入驻，应从平台控制账号创建和店铺归属，不能开放任意商户自行认领已有店铺。
