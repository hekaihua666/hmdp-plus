## 轻社交的具体设计

### 笔记：与门店关联，不向粉丝推送

BlogServiceImpl.saveBlog校验门店、标题、正文及图片数量，重新构建要保存的实体。作者取当前登录身份，初始点赞/评论为0；不接受客户端传入已有笔记ID、伪造作者、计数与时间。保存成功直接返回笔记ID，不遍历粉丝。

首页继续提供最新/热门笔记，门店详情继续展示本店笔记；“我的笔记”和作者笔记以创建时间、主键稳定排序，固定每页10条。作者资料与作者笔记允许游客阅读，发布、点赞、关注和个人列表仍须消费者登录。

公开资料接口只返回昵称、头像或简介/城市；不因为作者主页开放阅读而暴露生日、积分、会员级别等字段。

保留ZSet点赞：member为用户ID，score为点赞时间，用于点赞状态和最近5位点赞者。它不是“用户热度排行榜”。并发重复新增/移除时，只有实际改变member的请求调整数据库计数；网页也阻止一次操作完成前反复点击。

**边界：** 点赞ZSet和数据库计数没有跨存储事务，Redis数据丢失或跨存储写失败仍需核对。当前不为轻社交引入第二套MQ、持久点赞表或复杂排行榜，不能把这一教学功能宣传为强一致点赞系统。

### 关注：只维护MySQL一份关系

原来MySQL + Redis Set的关注双写已取消。关注接口表达目标状态，重复发送true不反复插入；取关移除对应关系。事务锁住当前用户行，让同一账号的关注写操作在多实例下也串行完成，避免“先查再插”并发产生重复关系。

本人列表按当前登录ID查询，EXISTS避免历史重复关系导致重复作者，只返回作者ID、昵称、头像，不返回手机号。分页按作者ID倒序，每页10人；取关后前端重新从第一页加载，避免删除记录后offset变化跳过作者。本轮不修改旧关系或引入数据库迁移。

保留接口：

- `PUT /follow/{authorId}/{true|false}`
- `GET /follow/or/not/{authorId}`
- `GET /follow/of/me?current=1`

退役：`GET /follow/common/{id}`、`GET /blog/of/follow`；不留假实现返回空集合冒充仍然可用。

### 页面：只展示可操作入口

个人页与作者页共用profile.js/profile.css，保留笔记与关注作者，不展示固定“粉丝(0)”、空评价、共同关注或未实现的资料编辑入口。列表有空态、加载、失败重试和加载更多。

底部导航改为“首页、附近、发布、关注、我的”。“附近”进入5公里距离排序，“关注”进入本人作者列表。笔记详情保留点赞、作者入口、门店入口，移除评论占位；正文按纯文本显示并兼容旧换行标签。

发布页提供必填校验、9图上限与防重复提交；multipart边界交给浏览器。照片上传需登录；从草稿移除照片仅修改当前草稿，不开放按公开图片路径删除服务器文件的接口。未实现上传文件所有权管理或未引用图片自动清理。

消费者退出接口会撤销当前Redis会话；浏览器在接口失败时仍完成本地退出，失败时服务端会话可能等待原TTL过期。

## 附近商户统一走ES

shop-search.js不再根据条件切换两套后端。分类、关键词、半径、排序、分页使用 `/shop/search`，同一响应包含列表、总数和三组聚合；不再同时请求GEO列表及另一份ES统计。

- 普通分类默认按距离排序，但不暗中截断为5公里；用户可查看该分类全部商户。
- “附近”导航显式携带 `sort=distance&radius=5000`；不限距离与各半径可在面板切换。
- 参考坐标仍是原杭州固定坐标，尚未接入设备定位，页面如实标注“杭州参考位置”。
- 缺少聚合桶或请求失败不会显示成0家；ES请求失败展示错误与重试，不静默切换另一套不同语义的数据源。
- `ShopGeoInitializer`、`IShopService.queryShopByType`及`/shop/of/type`已移除。商户提交后仍失效Redis详情缓存、异步同步ES，位置及分类自然进入同一搜索索引。
- `/shop/of/name`保留：它是发布笔记时选择关联门店的简单数据库查询，不是第二套附近检索。

商户ES提交后同步仍没有持久重试，本轮不将订单MQ接入扩大为商户ES Outbox改造。

## 代码阅读顺序

1. BlogServiceImpl、BlogController：发布白名单、公开阅读、点赞与最近点赞者。
2. FollowServiceImpl、FollowMapper、FollowController：单一关系源、用户行锁和本人列表。
3. profile.js、info.html、other-info.html：两种主页共用的分页和操作。
4. shop-search.js、ShopSearchServiceImpl：单次ES搜索、半径与距离排序、聚合。
5. ShopChangedEventListener：删去GEO以后保留的详情缓存失效与ES同步职责。

RocketMQ订单链路保持原设计，见[mq-design.md](mq-design.md)。
